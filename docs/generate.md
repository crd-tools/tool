# Генерация манифестов и список CRD

Как получить YAML-манифесты CRD и посмотреть, какие определения есть в проекте.
Читайте, когда настраиваете генерацию в проекте или CI.

## Пример

```go
package resources

var App = crd.New[apps.App]().
	Group("example.com").Kind("App").Plural("apps").
	Version("v1", true, true)

func init() {
	crd.Add(App)
}
```

```sh
go tool crd.tools generate ./resources                    # манифест в stdout
go tool crd.tools generate -o ./config/crd ./...          # файлы <group>_<plural>.yaml
go tool crd.tools generate --validate -o ./config/crd ./...  # с проверкой кодом API-сервера
go tool crd.tools list ./...                              # таблица найденных CRD
```

## Какие определения находятся

Инструмент находит пакеты, где `crd.Add` **вызывается в `init`**, и берёт
определения из `crd.List()`. Вызовы в других местах он не видит: они выполняются,
только когда их вызовет приложение, а `init` гарантированно выполняется до
`main`.

- Пакет `main` импортировать нельзя, поэтому определения в нём не находятся —
  выносите их в обычный пакет.
- Шаблоны пакетов задают точку входа, а не границу: если найденный пакет
  импортирует другой пакет с `crd.Add` в `init`, его определения тоже попадут в
  список. Сузить выбор можно фильтрами.

## Флаги

Флаги ставятся **до шаблонов пакетов**: `generate --kind App ./api`, а не
`generate ./api --kind App`. Это ограничение `urfave/cli` v2, команда сообщит о
неправильном порядке.

Общие для `generate` и `list`:

| Флаг | Назначение |
|---|---|
| `--kind`, `--group`, `--plural` | отбор определений: точное сравнение с учётом регистра |
| `--validate` | проверка каждого CRD кодом API-сервера |

Только `generate`:

| Флаг | Назначение |
|---|---|
| `-o`, `--output` | каталог для файлов вместо stdout |
| `--set-group`, `--set-kind`, `--set-plural`, `--set-singular`, `--set-scope` | заменить значение |
| `--set-short-names`, `--set-categories` | заменить список |
| `--set-label k=v`, `--set-annotation k=v` | добавить метку или аннотацию |

Флаги `--set-*` разрешены, только если после отбора остался ровно один CRD.
Фильтры сравнивают значения из определения до переопределений.

## generate

- **Файлы** называются `<group>_<plural>.yaml` и начинаются с
  `# Code generated by crd. DO NOT EDIT.`. Существующие перезаписываются,
  устаревшие не удаляются.
- **Совпадение имён** (одинаковые `group` и `plural`) нумеруется `_1`, `_2` с
  предупреждением в stderr. Такие CRD нельзя применить вместе: второй перезапишет
  первый.
- **Ошибки** всех CRD собираются вместе; если хоть один не собрался или не прошёл
  `--validate`, ничего не пишется. Без `--validate` проверяется только то, что
  ловит `Build`: обязательные поля, версия хранения, схемы.
- **Снимки** kubebuilder берутся как есть: перед генерацией обновите их через
  `kubebuild get`/`prune` ([kubebuild.md](kubebuild.md)).

## list

```
NAME                KIND      GROUP         PLURAL     SCOPE        VERSIONS     STATUS
-                   NoGroup   -             nogroups   -            -            error: crd: empty group
apps.example.com    App       example.com   apps       Namespaced   v1*          ok
users.example.com   User      example.com   users      Namespaced   v1*,v1beta1  ok
```

`*` отмечает версию хранения. Ошибки показываются в колонке `STATUS`, а не
прерывают список; если ошибки есть, команда завершается с ненулевым кодом.
Совпадения имён видны как повторяющиеся `NAME`.

### Формат вывода

Флаг `--format` (пакет [github.com/mantyr/formatter](https://github.com/mantyr/formatter)):

```sh
go tool crd.tools list --format json ./... | jq -r 'select(.status=="error") | .kind'
go tool crd.tools list --format yaml ./...
go tool crd.tools list --format '{{.Kind}} {{.Name}}' ./...
go tool crd.tools list --format 'table {{.Kind}}\t{{.Storage}}' ./...
```

| Значение | Вывод |
|---|---|
| `table` (по умолчанию) | таблица выше |
| `json` | объект на строку (JSON Lines) |
| `yaml` | документы через `---` |
| `raw` | поле `имя: значение` на строку |
| `table <шаблон>` | своя таблица с заголовком |
| `<шаблон>` | строка на элемент по шаблону `text/template` |

Поля: `.Name`, `.Kind`, `.Group`, `.Plural`, `.Scope`, `.Versions` (через
запятую), `.Storage`, `.Status` (`ok` или `error`), `.Error`; метод
`.VersionsMarked` — версии с `*` у версии хранения. Функции шаблонов: `join`,
`split`, `upper`, `lower`, `title`, `pad`, `truncate`, `json`, `yaml`. Ошибка в
шаблоне выводится как `--format: bad format`.

## Как это устроено

1. Поиск разбором AST: файлы с импортом `crd.tools/crd`, в них `init` с
   вызовом `crd.Add` (с учётом алиаса импорта).
2. Временный `main` в `_tmp/_crdgen/<id>/` внутри модуля — только так он может
   импортировать `internal`-пакеты. Каталоги с `_` Go пропускает при `./...` и
   `go mod tidy`. `main` импортирует найденные пакеты ради их `init`, подключает
   снимки из `crd.tool.yaml`, отбирает определения, применяет `--set-*`, собирает
   CRD и отдаёт их в JSON. После запуска каталог удаляется, `_tmp` — только если
   его создал инструмент.
3. `--validate` выполняется в процессе инструмента: временному `main`
   зависимости пакета проверки недоступны, `go mod tidy` проекта их не сохранит.
